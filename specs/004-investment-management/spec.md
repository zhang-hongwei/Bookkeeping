**Feature Branch**: `004-investment-management`
**Created**: 2026-06-29
**Status**: Draft
**Input**: User description: "继续完成 docs/product-design/ai-wealth-manager.md 指定全部的规格"（本 spec 对应《AI 财富管家产品设计》中的 **Phase 3**，依赖 Phase 0 复式记账 + Phase 1 净资产 + Phase 2 资产/负债）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 买入/卖出后，持仓和净资产都对 (Priority: P1)

作为一个买基金/股票的人，我希望记录一笔「用银行卡买入 ¥1,000 某基金」后，银行卡少 ¥1,000、该基金持仓 +¥1,000 成本、净资产不变；卖出时如实记录盈亏。

**Why this priority**: 投资的核心不变式——「资金从现金变为持仓，净资产不变」——是投资模块正确性的地基。没有它，持仓成本、收益、净资产都会崩。它复用 Phase 0 复式记账，是投资闭环能否成立的试金石。

**Independent Test**: 记录「银行卡 −¥1,000 → 某基金 +¥1,000」，系统正确呈现：现金 −¥1,000、基金持仓 +¥1,000（成本）、净资产不变、持仓数量/成本价正确。

**Acceptance Scenarios**:

1. **Given** 用户银行卡有 ¥5,000，**When** 买入某基金 ¥1,000（份额按当日净值），**Then** 银行卡 −¥1,000，该基金持仓 +¥1,000 成本，**净资产总额不变**。
2. **Given** 用户持有某基金成本 ¥1,000，**When** 卖出其中一部分得到 ¥1,200，**Then** 现金 +¥1,200，持仓成本按比例减少，¥200 盈亏如实计入，净资产如实反映盈亏。
3. **Given** 用户在投资账户与现金账户间转账（如银行卡 → 证券账户），**When** 记录，**Then** 仅资金位置变化，净资产与持仓均不变。

---

### User Story 2 - 自动看到持仓的市值、收益与收益率 (Priority: P2)

作为一个长期持有的人，我希望能随时看到每个持仓的当前市值、累计成本、浮动盈亏和收益率，而不是只有买入成本。

**Why this priority**: 收益与收益率是投资决策的核心信息。接入行情现价、计算市值/盈亏/收益率，让「我投的赚没赚」一目了然，是投资模块的价值产出。

**Independent Test**: 给定持仓（数量/成本价）与现价，系统正确计算市值、成本、盈亏、盈亏率，盈亏 = 市值 − 成本，盈亏率 = 盈亏 / 成本。

**Acceptance Scenarios**:

1. **Given** 用户持有某基金 1000 份、成本价 ¥1.00，**When** 现价更新为 ¥1.20，**Then** 显示市值 ¥1,200、成本 ¥1,000、盈亏 +¥200、盈亏率 +20%。
2. **Given** 多个持仓，**When** 查看投资总览，**Then** 汇总总市值、总成本、总盈亏与综合收益率，且单持仓可下钻。
3. **Given** 行情数据缺失或陈旧，**When** 查看持仓，**Then** 系统标注行情时间/来源，并允许用户手动输入/修正现价（降级），不展示虚假最新价。

---

### User Story 3 - 基金定投的累计投入、市值与年化收益（IRR） (Priority: P3)

作为一个每月定投基金的人，我希望能记录定投历史，看到累计投入、当前市值，以及考虑了资金时间价值的真实年化收益（IRR），而不是简单的算术平均。

**Why this priority**: 定投是最常见的长期投资方式，IRR 是衡量「多笔不同时点投入」真实回报的标准方法。把它做对，投资收益评估才可信，避免「算术收益率」误导。

**Independent Test**: 记录一笔按月定投（多笔不同时点买入），系统计算累计投入、当前市值，IRR 与主流基金计算器（如天天基金）结果一致。

**Acceptance Scenarios**:

1. **Given** 用户每月定投某基金 ¥1,000 共 12 个月，**When** 查看定投记录，**Then** 显示累计投入 ¥12,000、当前市值、累计盈亏。
2. **Given** 上述定投历史，**When** 计算 IRR，**Then** 给出考虑资金时间价值的年化收益率，结果与主流基金 IRR 计算器一致。
3. **Given** 用户中断/恢复定投，**When** 记录，**Then** IRR 基于实际投入时点正确重算。

---

### User Story 4 - 我的钱都投在了哪里（资产配置与集中度） (Priority: P4)

作为一个分散投资的人，我希望能看到投资在股票/债券/黄金/现金等各类资产的占比，并在某类资产过于集中时被提醒。

**Why this priority**: 资产配置决定长期风险收益。配置占比 + 集中度预警把投资从「记一笔」升级为「看得见风险」，是投资顾问的雏形。

**Independent Test**: 给定多个不同类型持仓，系统按股/债/金/现金等维度汇总占比并绘制配置图；某单一品种占比超过阈值时给出集中度预警。

**Acceptance Scenarios**:

1. **Given** 用户有股票、债券、黄金、现金多个持仓，**When** 查看资产配置，**Then** 按类型汇总占比并可视化呈现。
2. **Given** 某单一持仓/品种占比超过预设阈值（如 60%），**When** 触发检查，**Then** 系统给出集中度预警提示（仅提示，不代为操作）。

---

### Edge Cases

- **行情来源不可用**：第三方行情不稳定（设计第 4 章可行性 ★★★），需降级为用户手动输入现价，并标注行情时间/来源，不展示虚假价格（对应 D3 默认）。
- **分红/派息/送股**：需如实反映为持仓数量/成本调整或现金流入，不扭曲收益。
- **手续费/印花税**：买入/卖出的费用应正确计入成本或从收益扣除，不可静默忽略。
- **份额精度与四舍五入**：份额/净值需保留足够精度，避免累计误差导致市值与成本对不上。
- **跨市场/跨币种标的**：本阶段聚焦 CNY 标的；QDII/港美股等跨币种不在本阶段。
- **IRR 无法收敛**：投入与回收时点极端时 IRR 可能无解或多解，需给出明确提示而非错误数值。
- **持仓清零/退出**：全部卖出后持仓归零、盈亏如实计入历史，净资产如实反映。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持投资账户与持仓：持仓含品种代码、品种类型（股票/基金/债券/黄金/ETF/REITs/数字货币）、数量、成本价、现价，及派生字段市值/成本/盈亏/盈亏率。
- **FR-002**: 系统 MUST 保证「现金买入持仓」时：现金账户 −金额、持仓 +金额成本、净资产不变（沿用复式不变式）；卖出时如实记录盈亏、净资产如实反映。
- **FR-003**: 系统 MUST 接入行情现价（股票/基金/黄金等）用于计算持仓市值与盈亏；盈亏 = 市值 − 成本，盈亏率 = 盈亏 / 成本。
- **FR-004**: 系统 MUST 在行情不可用/陈旧时降级为用户手动输入现价，并标注行情时间与来源，不展示虚假最新价。
- **FR-005**: 系统 MUST 支持基金定投：记录多笔不同时点买入，汇总累计投入、当前市值，并计算考虑资金时间价值的年化 IRR。
- **FR-006**: 系统 MUST 正确处理分红/派息/送股与交易手续费：如实反映为持仓或现金变动、计入成本或收益，不扭曲盈亏。
- **FR-007**: 系统 MUST 提供资产配置分析：按股/债/金/现金等维度汇总投资占比并可视化；单一品种占比超阈值时给出集中度预警（仅提示，不代为操作）。
- **FR-008**: 系统 MUST 在持仓现价变动后同步更新净资产快照（投资类资产按市值计入），曲线不留存旧值。
- **FR-009**: 系统 MUST 保证所有数据按用户隔离，用户只能查看与操作自己的投资账户与持仓。

### Key Entities *(include if feature involves data)*

- **持仓 (Position)**：投资账户上的资产状态，含品种代码/类型、数量、成本价、现价，及派生的市值/成本/盈亏/盈亏率；现价来自行情来源并带时间戳。
- **投资交易 (Investment Trade)**：买入/卖出/分红等投资动作，产生复式分录（现金 ↔ 持仓），与 Phase 0 交易/分录体系打通。
- **品种 (Instrument)**：股票/基金/债券/黄金/ETF/REITs/数字货币等可投资标的，含行情缓存（现价、来源、时间）。
- **定投记录 (DCA Record)**：按周期多笔买入的记录，用于累计投入、市值汇总与 IRR 计算。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：「银行卡 −¥1,000 → 基金 +¥1,000」后，现金、持仓成本、净资产三者关系正确（净资产不变、持仓 +¥1,000 成本），错账发生率 = 0。
- **SC-002**：IRR 计算结果与主流基金 IRR 计算器（如天天基金定投收益）在相同投入/市值下一致（允许末位四舍五入差异）。
- **SC-003**：持仓盈亏 = 市值 − 成本、盈亏率 = 盈亏 / 成本，在现价更新后即时正确，与逐项手动核算一致，不一致发生率 = 0。
- **SC-004**：行情不可用时，系统降级为手动输入现价并标注来源/时间，无虚假最新价展示。
- **SC-005**：资产配置占比按类型正确汇总，单一品种占比超阈值时准时给出集中度预警。

## Assumptions

- 本阶段依赖 Phase 0（复式记账）、Phase 1（净资产快照）、Phase 2（资产/负债含投资类资产项）。
- 行情数据来自第三方行情源（对应设计 D3 默认：第三方 API，失败降级为手动输入）；行情稳定性/授权需在实现阶段评估。
- 本阶段聚焦 CNY 标的（A 股/公募基金/黄金等）；跨币种（QDII/港美股/外币 crypto）不在本阶段。
- IRR 采用考虑资金时间价值的标准方法（与主流基金计算器口径一致）。
- 资产配置与集中度预警仅作提示，不构成投资建议、不代为交易（对应设计第 9 章合规免责）。
- 用户已登录，所有数据按用户隔离，身份与权限沿用项目现有机制。
- 沿用领域原则：持仓/市值走领域模型，分析结论走规则引擎。
