## User Scenarios & Testing *(mandatory)*

### User Story 1 - 提前预知我的现金流会不会出问题 (Priority: P1)

作为一个想未雨绸缪的人，我希望系统能基于我的历史收支预测未来几个月的现金流，提前告诉我「按这个节奏，3 个月后应急金会不足」。

**Why this priority**: 从「看过去」到「看未来」是产品北极星「未来会怎样」的核心兑现。现金流预测 + 智能预警，把顾问从「事后报告」升级为「事前预警」，是差异化的高价值能力。

**Independent Test**: 给定足够历史收支，系统预测未来数月现金流趋势；当预测出现「应急金不足/持续赤字」等情形时，提前给出可追溯至规则结论的预警。

**Acceptance Scenarios**:

1. **Given** 用户有数月历史收支，**When** 查看现金流预测，**Then** 呈现未来数月预测趋势，并标注其基于历史 + 规则。
2. **Given** 预测显示应急金将在 N 月后不足，**When** 触发，**Then** 系统提前给出预警，且预警依据可追溯到规则结论。
3. **Given** 用户调整了收支（如削减某类支出），**When** 重新预测，**Then** 预测与预警随之刷新。

---

### User Story 2 - 和我的财务顾问对话，建议都可信、可追溯 (Priority: P2)

作为一个想要个性化建议的人，我希望能用自然语言和「财务顾问」对话，问「我该不该提前还房贷」「储蓄率怎么提」，得到的建议基于我的真实数据、且高风险动作需我确认才生效。

**Why this priority**: 个性化顾问对话是产品「AI 财富顾问」定位的直接体现。关键是红线——建议基于规则结论、高风险动作走审批闭环（提议→规则校验→用户审批→落库），保证可信与可控。

**Independent Test**: 用户提问「储蓄率怎么提」，顾问基于规则结论给出个性化建议；提出高风险动作（如「标记某交易为异常」「建议调仓」）时，必须经用户审批后才落库。

**Acceptance Scenarios**:

1. **Given** 用户与顾问对话提问，**When** 顾问回答，**Then** 回答中的财务数字/结论来自规则引擎，不编造。
2. **Given** 顾问提出高风险动作建议，**When** 用户未审批，**Then** 该动作不得自动落库；必须经规则校验 + 用户审批后才生效。
3. **Given** 顾问建议，**When** 用户查看，**Then** 每条建议可追溯到其依据的规则结论/数据。

---

### User Story 3 - 看到我的财务状况随时间的变化趋势 (Priority: P3)

作为一个长期使用者，我希望能对比多期报告，看到储蓄率/负债率/健康分等指标随时间是在变好还是变差。

**Why this priority**: 趋势对比把单期快照串成「成长曲线」，强化长期留存与价值感。复用已有报告与规则结论，杠杆高。

**Independent Test**: 生成多期报告后，系统对比关键指标（储蓄率/负债率/健康分）随时间的变化趋势。

**Acceptance Scenarios**:

1. **Given** 用户有多期历史报告，**When** 查看趋势对比，**Then** 关键指标随时间的变化可可视化呈现。
2. **Given** 某指标显著恶化（如健康分连续下降），**When** 触发，**Then** 系统给出趋势预警与改善建议。

---

### Edge Cases

- **预测不确定性**：预测必须标注其不确定性/置信区间，避免呈现为确定性事实；历史数据不足时明确提示「数据不足以可靠预测」。
- **高风险动作审批失败/拒绝**：审批被拒或规则校验未通过时，动作不落库，并给出明确原因。
- **LLM 幻觉红线**：任何涉及具体金额/风险评级/投资建议的判断必须来自规则引擎；LLM 失败降级为模板文本（沿用 Phase 1 红线）。
- **预警疲劳**：预警须可配置/可静默，避免过多打扰导致用户忽略。
- **历史数据不足**：新用户或数据稀疏时，预测/画像须明确降级提示，不编造结论。
- **合规免责**：所有建议/预测显著标注「非投资建议」，引用规则依据（沿用设计第 9 章）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 基于历史收支 + 规则提供未来数月现金流预测，并标注预测的不确定性/置信；历史不足时明确提示降级。
- **FR-002**: 系统 MUST 提供智能预警：对应急金不足/储蓄率下降/负债占比过高等情形提前预警，且预警依据可追溯到规则结论。
- **FR-003**: 系统 MUST 提供个性化顾问对话：自然语言问答，回答中的财务数字/结论来自规则引擎（不编造），LLM 负责表达与个性化。
- **FR-004**: 系统 MUST 对高风险动作（如标记异常交易、建议调仓、修改财务结论）走审批闭环：LLM 提议 → 规则校验 → 用户审批 → 才落库；未审批不得自动生效。
- **FR-005**: 系统 MUST 支持多期报告趋势对比：关键指标（储蓄率/负债率/健康分等）随时间的变化可视化，显著恶化时给出趋势预警。
- **FR-006**: 系统 MUST 完成财务健康评分体系（在 Phase 1 基础上完善维度与口径），评分确定性、可复现。
- **FR-007**: 系统 MUST 保证所有预测/建议/预警的数值结论可追溯到规则与账目数据；LLM 失败降级为模板文本。
- **FR-008**: 系统 MUST 允许用户配置/静默预警，避免预警疲劳。
- **FR-009**: 系统 MUST 在所有建议/预测上显著标注「非投资建议」并引用规则依据。
- **FR-010**: 系统 MUST 保证所有数据按用户（及家庭成员）隔离。

### Key Entities *(include if feature involves data)*

- **现金流预测 (Cash Flow Forecast)**：基于历史收支与规则的未来趋势预测，含置信/不确定性标注。
- **智能预警 (Smart Alert)**：由规则触发的提前预警（应急金/储蓄率/负债/趋势），含规则结论依据。
- **顾问会话 (Advisor Session)**：个性化自然语言顾问对话，结论来自规则引擎、表达来自 LLM。
- **审批闭环 (Approval Loop)**：高风险动作的提议→校验→审批→落库流程（复用项目既有审批管道）。
- **趋势对比 (Trend Comparison)**：多期报告关键指标的时间序列对比。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：现金流预测与智能预警在历史回测中达到可接受的准确率（具体阈值在临近实施时按真实数据标定，本 spec 不预先固化）。
- **SC-002**：所有预测/建议/预警的数值结论 100% 可追溯到规则结论/账目数据；LLM 不编造金额/风险数字。
- **SC-003**：高风险动作 100% 走审批闭环，未经用户审批的动作绝不落库。
- **SC-004**：多期趋势对比正确反映关键指标随时间的变化，与各期报告结论一致。
- **SC-005**：LLM 服务异常时，预测/建议降级为规则结论模板文本，关键结论不丢失。

## Assumptions

- 本阶段依赖 Phase 0–5 完整财务模型与规则引擎，并复用项目既有 AI Pipeline / 审批管道。
- 预测/预警的具体准确率阈值、置信区间口径需在临近实施时基于真实数据标定，本 spec 仅锁定「须可追溯、须标注不确定性」。
- 沿用设计 P5「规则引擎负责准确，LLM 负责表达」与 Phase 1 红线（高风险走审批、LLM 失败降级）。
- 本阶段为远期规划，领域实体/算法细节（预测模型、趋势口径）留待 `/speckit-plan` 临近时细化，可能产生实现期澄清点。
- 用户已登录，所有数据按用户隔离；建议均标注「非投资建议」。
- 沿用领域原则：结论走规则引擎，对话/报告走 LLM 表达层。
