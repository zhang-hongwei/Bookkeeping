## User Scenarios & Testing *(mandatory)*

### User Story 1 - 把我的全部家底都登记进来 (Priority: P1)

作为一个有房有车也有贷款的人，我希望能把房产、车辆、房贷、车贷、信用卡欠款、借款都登记进系统，让「总资产 − 总负债 = 净资产」真正反映我的全部家底，而不只是现金。

**Why this priority**: Phase 1 只算了现金/存款/信用。对一个普通中国家庭，房产和房贷往往占净资产的大头，不把它们纳入，净资产就是失真的。把资产/负债做全是「诚实净资产」的前提。

**Independent Test**: 用户登记一套房产（带估值与置信度）、一辆车、一笔房贷、一笔车贷、信用卡欠款后，仪表盘总资产/总负债/净资产正确反映全部家底，且实物资产在曲线上被单独标记，可与高流动性资产切换查看。

**Acceptance Scenarios**:

1. **Given** 用户想登记一套房产，**When** 录入房产名称、当前估值 ¥3,000,000 并标注估值置信度，**Then** 该房产计入总资产，且在净资产曲线上被标记为「估值点」（非现金类）。
2. **Given** 用户登记一笔房贷（本金 ¥2,000,000、剩余本金、利率、月供、到期日），**When** 保存，**Then** 剩余本金计入总负债，月供/到期信息保留。
3. **Given** 用户查看净资产曲线，**When** 切换「仅高流动性资产」视图，**Then** 房产/车辆等低流动性估值资产被过滤，仅显示现金/投资类，且可一键切回「全部资产」。
4. **Given** 用户登记的全部家底，**When** 查看仪表盘，**Then** 净资产 = 总资产 − 总负债，且分项明细可展开查看每项资产/负债的来源与置信度。

### User Story 2 - 还了一笔贷款，账目和净资产都对得上 (Priority: P2)

作为一个每月在还房贷/车贷/信用卡的人，我希望记录一笔还款后，负债正确减少、现金正确减少、净资产平滑反映，而不是出现错账或净资产跳变。

**Why this priority**: 还款是最高频的负债变动场景，也是检验复式记账在负债场景正确性的关键。一笔还款必须同时减少「负债」和「现金」，净资产按利息部分平滑变化——这是「负债完整化」是否真正可用的试金石。

**Independent Test**: 记录一笔房贷还款（本金 ¥3,000 + 利息 ¥2,000 = ¥5,000），系统正确拆分本金/利息：剩余负债 −¥3,000、现金 −¥5,000、净资产因利息支出 −¥2,000，资产端不变。

**Acceptance Scenarios**:

1. **Given** 用户有一笔房贷剩余本金 ¥1,500,000，**When** 记录一笔还款 ¥5,000（本金 ¥3,000 / 利息 ¥2,000），**Then** 剩余本金变为 ¥1,497,000，现金 −¥5,000，利息 ¥2,000 如实计入支出，资产端不变。
2. **Given** 用户有一笔信用卡欠款，**When** 记录还款，**Then** 信用类负债减少、还款账户现金减少，净资产如实反映。
3. **Given** 用户查看净资产曲线，**When** 上述还款发生，**Then** 曲线因利息支出平滑下降，不因本金/负债的等额对冲产生虚假波动。

### User Story 3 - 信用卡账单周期与还款日 (Priority: P3)

作为一个用信用卡消费的人，我希望能设置信用卡的账单日和还款日，看到本期账单金额、是否已还清，避免逾期。

**Why this priority**: 信用卡是中国人最常用的负债工具。把账单周期/还款日/免息期纳入，让信用负债从「一个余额」升级为「可管理的账单」，是负债完整化的必备细节。

**Independent Test**: 设置一张信用卡的账单日/还款日，系统按周期汇总本期账单金额，标记还款状态，临近还款日给出提示。

**Acceptance Scenarios**:

1. **Given** 用户有一张信用卡，**When** 设置账单日（如每月 5 日）与还款日（如每月 25 日），**Then** 系统按账单周期汇总「本期账单金额」与「已还金额」，显示剩余待还。
2. **Given** 账单已生成，**When** 临近还款日，**Then** 系统给出还款提示（不自动还款、不代扣）。
3. **Given** 用户全额还款，**When** 记录还款，**Then** 本期账单标记为已还清，信用负债归零。

### Edge Cases

- **实物资产估值波动**：房产/车辆估值不是市场实时价，必须带 `estimateConfidence`（如高/中/低），低置信度估值在主曲线上单独着色/过滤，不与现金混为一谈（对应设计 P6「诚实估值」、D2 默认不计入主曲线）。
- **负债利率为 0 或无固定还款**（如亲友借款）：允许登记无利率/无固定月供的负债，到期日/月供应设为可选。
- **提前还款 / 缩短周期**：支持提前还款并正确重算剩余本金与到期。
- **资产贬值**（如车辆）：允许更新估值并重算净资产，需保留估值历史以便回溯。
- **跨币种负债**：仍为单币种 CNY，外币负债不在本阶段。
- **实物资产出售/处置**：出售资产应正确从总资产移除、现金等额增加，净资产如实反映（不产生虚假收益除非有实际盈亏）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持登记完整资产明细，覆盖现金/存款、基金/股票/债券/黄金（投资类）、房产、车辆、数字货币等；每项含当前价值、成本、来源、估值置信度。
- **FR-002**: 系统 MUST 支持登记完整负债明细，覆盖房贷/车贷/信用卡/消费贷/借款；含本金、剩余本金、利率、月供、到期日、已还金额。
- **FR-003**: 系统 MUST 对房产/车辆等低流动性资产标注估值置信度，并在净资产曲线上将此类「估值点」与高流动性资产区分呈现，支持「仅高流动性资产」/「全部资产」视图切换。
- **FR-004**: 系统 MUST 支持贷款还款：正确拆分本金与利息——本金减少负债、本金+利息合计减少现金、利息计入支出、资产端不变；并保持账目平衡（复式不变式）。
- **FR-005**: 系统 MUST 在还款后同步更新剩余本金、已还金额、（若提前还款）到期日，净资产曲线平滑反映利息支出，不因本金/负债对冲产生虚假波动。
- **FR-006**: 系统 MUST 支持信用卡账单周期：设置账单日/还款日，按周期汇总本期账单金额与已还金额，显示剩余待还；临近还款日给出提示（不自动代扣）。
- **FR-007**: 系统 MUST 保证净资产 = 总资产 − 总负债，涵盖全部登记的资产与负债，与逐项汇总一致。
- **FR-008**: 系统 MUST 在资产估值更新、负债变动后，同步更新相关日期净资产快照（沿用 Phase 1 快照机制），曲线不留存旧值。
- **FR-009**: 系统 MUST 保证所有数据按用户隔离，用户只能查看与操作自己的资产/负债。

### Key Entities *(include if feature involves data)*

- **资产 (Asset)**：现金/存款/投资/房产/车辆/数字货币等资产明细，含当前价值、成本、来源、估值置信度。现金/存款类由账户余额聚合，投资类由持仓（Phase 3）驱动，实物类由用户输入估值。
- **负债 (Liability)**：房贷/车贷/信用卡/消费贷/借款明细，含本金、剩余本金、利率、月供、到期日、已还金额。信用类可与账户（Phase 0 信用账户）关联并承载账单周期。
- **估值置信度 (Estimate Confidence)**：标注资产估值的可靠性（如高/中/低），用于在净资产曲线上区分高流动性资产与低流动性估值资产。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：一笔房贷/车贷/信用卡还款后，剩余负债、现金、净资产三者的变动均正确（本金对冲不扭曲净资产，仅利息部分改变净资产），错账发生率 = 0。
- **SC-002**：登记房产/车辆等实物资产后，其在净资产曲线上被正确标记为「估值点」，且可一键切换「仅高流动性资产」视图过滤之。
- **SC-003**：净资产 = 总资产 − 总负债 在涵盖全部资产/负债时始终成立，与逐项手动汇总一致，不一致发生率 = 0。
- **SC-004**：信用卡账单日/还款日设置后，本期账单金额与已还金额按周期正确汇总，临近还款日准时提示。
- **SC-005**：资产估值更新或负债变动后，净资产曲线相关日期同步刷新，无历史旧值残留。

## Assumptions

- 本阶段依赖 Phase 0（复式记账地基）与 Phase 1（净资产快照/曲线机制）。
- 投资类资产（股票/基金/黄金）的实时市值与持仓细节属 Phase 3；本阶段投资类资产以用户输入或简单估值为准，不强制接入行情。
- 实物资产估值由用户输入并标注置信度，本阶段不接入房产/车辆估值 API（对应设计 D3 之外、第 4 章「房产/车辆估值可行性 ★★」）。
- 单币种 CNY；外币资产/负债不在本阶段。
- 信用卡不自动还款、不代扣、不存储任何凭证（对应设计第 9 章安全/合规：不存凭证）。
- 用户已登录，所有数据按用户隔离，身份与权限沿用项目现有机制。
- 沿用领域原则：领域模型是真相源，估值/负债明细走领域模型而非文档。
