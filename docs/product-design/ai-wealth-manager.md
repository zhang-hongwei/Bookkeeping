# AI 财富管家 — 完整产品设计（分版本路线图）

> 状态：产品设计 / 路线图
> 日期：2026-06-29
> 范围：从当前「餐食记账 + 多模态 AI 对话」演进为「以净资产为核心的 AI 财富管家」
> 约束：本规划**不考虑开发成本**（可分多版本交付），但仍尊重不可绕开的产品/市场硬约束（中国大陆数据获取、合规与信任）。

---

## 0. 一句话定位

**不是记账软件，是「个人 CFO」**：核心不回答「我花了什么」，而回答「我变富了吗 / 未来会怎样 / 如何更有钱」。一切功能服务于一条北极星——**净资产曲线**。

---

## 1. 产品哲学（决策总纲）

| # | 原则 | 含义 |
|---|------|------|
| P1 | **净资产为中心** | 所有模块的终极产出是「净资产」及其变化。流水只是原料。 |
| P2 | **复式记账为地基** | 任何资金移动 = 一笔平衡的双边分录。没有它，投资/转账必然崩。 |
| P3 | **领域模型是真相源，文档是报告层** | 财务数值/事务走关系型领域模型；Block/文档只承载「分析报告 / 财务日志」，**不**用文档当财务真相源。 |
| P4 | **数据获取优先于漂亮仪表盘** | 录入摩擦是头号死亡线。每个版本都要把「降低录入摩擦」当成一等公民。 |
| P5 | **规则引擎负责准确，LLM 负责表达** | 财务结论（负债率/储蓄率/超支）走确定性规则；LLM 只做自然语言解释与个性化建议。高风险判断走审批/Hook。 |
| P6 | **诚实估值** | 房产/车辆等低流动性资产必须标注「估值/置信度」，不可与现金混为一谈，避免污染净资产曲线。 |

## 2. 总体架构

```
┌─────────────────────────────────────────────────────────────┐
│                     表现层 (Presentation)                     │
│   仪表盘 / 净资产曲线 / 报表 / AI 财务报告(Block/文档)         │
└──────────────▲──────────────────────────────────┬───────────┘
               │ 读                                │ 生成报告 artifact
┌──────────────┴──────────────────┐ ┌─────────────▼────────────┐
│        领域真相源 (Truth)         │ │     AI 财富顾问层          │
│  accounts / transactions /        │ │  规则引擎 ──► 结论(确定)    │
│  entries(复式) / positions /      │ │      + LLM ──► 表达(语言)   │
│  assets / liabilities / budgets / │ │      经 AI Pipeline + 审批  │
│  goals / snapshots / categories   │ └─────────────▲────────────┘
└──────────────▲──────────────────────────────────┘             │
               │ 写(事务/平衡约束)                              │ 洞察数据
┌──────────────┴────────────────────────────────────────────────┴─┐
│                   数据接入层 (Acquisition) —— 头号战场            │
│ 银行流水CSV / 支付宝·微信账单导出 / 截图OCR / 自然语言 / 行情API / 手动 │
└──────────────────────────────────────────────────────────────────┘
```

**关键边界**：
- `entries`（复式分录）是财务正确性的唯一锚点。`transactions` 是业务语义（一笔交易拆成多条 entries）。
- `snapshots` 做净资产曲线物化（每日/触发式），避免实时聚合历史全量流水。
- AI 报告产物落到现有文档/Block 体系（复用 product-agent + AI Pipeline），它**读**真相源、**写**报告，**不**反向写财务数据（除非走带审批的「建议→采纳→落库」闭环）。

## 3. 领域模型（技术核心）

> 命名沿用项目 Drizzle 风格（`src/database/schemas/`，复数 snake_case，`...timestamps`，`userId` + `onDelete: cascade`）。

### 3.1 accounts（账户 = 钱存放的位置）

| 字段 | 说明 |
|------|------|
| `id, userId, name` | |
| `type` | enum: `cash` / `savings` / `credit` / `investment` / `real_asset` |
| `currency` | 默认 CNY |
| `balance` | 当前余额（由 entries 汇总，或定期物化） |
| `creditLimit, statementDay, repaymentDay` | 仅 credit |
| `includeInNetWorth` | 是否计入净资产（实物资产可配） |
| `isArchived` | |

### 3.2 transactions + entries（复式记账）

```
transactions          一笔业务事件
  id, userId, type(income/expense/transfer/invest/loan/repay),
  occurredAt, note, source(manual/import/ocr/voice/agent), confidence

entries               复式分录腿（核心正确性锚）
  id, transactionId, accountId, side(debit/credit), amount
  约束：同一 transaction 的 Σdebit == Σcredit（事务级校验）
```

**规则**：转账/投资**不计收入支出**。`银行卡 -100 → 基金 +100` 产生两条平衡 entries，净资产不变。`income/expense` 用「权益/虚拟账户」做对腿以满足复式平衡（推荐引入隐式 `equity:income` / `equity:expense` 账户，使全套账目恒等式 `Σ资产 = Σ负债 + Σ权益` 成立）。

### 3.3 categories（分类）

收入（工资/奖金/兼职/分红/利息/租金…）、支出（餐饮/购物/住房/交通/医疗/教育/娱乐/旅游/宠物/孩子…）、转账、投资、借贷。可自定义，支持父子层级 + 关键字自动归类。

### 3.4 positions（投资持仓 = 投资账户上的资产状态）

| 字段 | 说明 |
|------|------|
| `id, accountId(investment), instrumentCode, instrumentType` | instrumentType: stock/fund/bond/gold/etf/reits/crypto |
| `quantity, costPrice, currentPrice` | |
| `marketValue, cost, pnl, pnlRate` | 派生：收益 = 市值 - 成本；收益率 = pnl/cost |
| `lastPriceAt, priceSource` | 行情来源 + 时间戳 |

### 3.5 assets / liabilities（资产/负债明细，支持非持仓类）

- `assets`：现金/存款（=账户余额聚合）/ 基金/股票/债券/黄金/房产/车辆/数字货币，含 `currentValue, cost, source, estimateConfidence`。
- `liabilities`：房贷/车贷/信用卡/消费贷/借款，含 `principal, remainingPrincipal, rate, monthlyPayment, dueAt, paidAmount`。

### 3.6 budgets / goals

- `budgets`：`category, period(monthly), limit, spent(派生), remaining(派生), status`。
- `goals`：`name, targetAmount, currentAmount(派生), targetAt, progressRate(派生), estAchieveAt(派生)`。

### 3.7 snapshots（净资产曲线物化）

每日/触发式快照：`date, totalAssets, totalLiabilities, netWorth, byTypeBreakdown(jsonb)`。曲线读这张表，不实时聚合。

### 3.8 ai_reports（AI 报告产物元数据）

报告本身内容落到文档/Block；此表记录 `period, type, score, generatedAt, approvedBy, sourceDataHash`（用于检测数据变化后失效）。

### 3.9 families / members（家庭，后期）

`families` + `family_members(userId, role, shareScope)`，交易带 `memberId`（谁花的/谁赚的），支持个人视图与家庭合并视图。

## 4. 数据接入策略（头号死亡线）

中国大陆个人开发者拿不到银行/券商开放 API。所以走**多通道组合**，按「自动 → 半自动 → 手动」分级：

| 通道 | 说明 | 自动度 | 可行性 |
|------|------|--------|--------|
| **支付宝/微信账单导出** | 两者官方支持导出 CSV（带交易类型/对手/分类）。最稳定的主通道。 | 半自动（导入） | ★★★★★ |
| **银行流水 CSV/Excel** | 招行/工行等网银导出流水，按银行做 parser 适配。 | 半自动 | ★★★★ |
| **截图 OCR** | 复用多模态 AI（现成能力）：账单/支付截图 → 识别交易。Agent 解析 + 人工确认。 | 半自动 | ★★★★ |
| **自然语言记账** | 「午饭 35」「打车 18 去公司」→ 解析为交易。AI 对话直接产生。 | 高 | ★★★★★ |
| **行情 API** | 股票/基金/黄金现价：第三方行情源（需评估授权/稳定性）。 | 自动 | ★★★ |
| **手动录入** | 兜底，UX 必须极轻。 | 手动 | ★★★★★ |
| **房产/车辆估值** | 无可靠 API → 用户输入 + 标注 `estimateConfidence`，曲线单独标记。 | 手动 | ★★ |

**设计纪律**：每条导入数据带 `source` + `confidence`；低置信度（OCR/估值）在净资产曲线上**单独着色/过滤**，不污染主曲线。

## 5. AI 财富顾问架构（差异化所在）

### 5.1 双层模型

```
   真相源数据
      │
      ▼
┌─────────────── 规则引擎（确定性结论）──────────────┐
│ 储蓄率/负债率/投资率/应急金月数/现金流趋势/超支检测 │
│  → 产出结构化结论：{metric, value, verdict, risk}   │  ← 可测试、可审计、零幻觉
└────────────────────────┬──────────────────────────┘
                         │ 结论作为事实喂给 LLM
                         ▼
┌─────────────── LLM（表达与个性化）─────────────────┐
│ 把规则结论翻成自然语言 + 个性化建议 + 语气适配      │  ← 只解释，不下判断
│  → 产出 AI 财务报告（落文档/Block）                │
└────────────────────────────────────────────────────┘
```

**红线**：涉及具体金额结论、风险评级、投资建议的判断**必须**由规则引擎产出；LLM 不得自行推算「你房贷占比 60%」这类数字。LLM 失败时降级为规则结论的模板文本。

### 5.2 与现有 AI Pipeline / Agent / Hook 对齐

- 报告生成走 **AI Pipeline**（复用现有），产物落到 Block/文档。
- 高风险动作（如「建议调仓」「标记某交易为异常」）走**审批管道**（042/043 既有）：LLM 提议 → 规则校验 → 用户审批 → 才落库。
- 自然语言记账与多模态账单解析直接挂到现有**多模态 AI 对话**（009 分支）。

## 6. 财务健康评分模型（0–100）

| 维度 | 计算 | 权重(建议) | 健康阈值 |
|------|------|-----------|----------|
| 储蓄率 | 月结余 / 月收入 | 25% | ≥20% 良好 |
| 负债率 | 总负债 / 总资产（或 月供 / 月收入） | 25% | ≤50% 良好 |
| 应急金 | 现金类 / 月支出（月数） | 20% | ≥3–6 月 |
| 投资率 | 投资资产 / 总资产 | 15% | 视年龄 |
| 现金流稳定性 | 近 3–6 月结余方差/趋势 | 15% | 持续为正 |

输出：总分 + 各维度雷达图 + LLM 生成的「一句话评语 + Top3 改进项」。

## 8. 分版本路线图

> 每个阶段标注：**目标 / 核心交付 / 领域模型增量 / AI 能力 / 退出标准**。
> 不考虑开发成本 = 可以在每个版本做「正确但重」的事，但仍按价值与依赖排序。

### Phase 0 — 地基：复式记账核心（v0.5）
- **目标**：建立不可崩的财务真相源。
- **交付**：`accounts` / `categories` / `transactions` / `entries`（复式+平衡约束）；现金·储蓄·信用账户；手动录入 + 支付宝/微信账单 CSV 导入。
- **模型增量**：accounts, categories, transactions, entries, equity 隐式账户。
- **AI**：自然语言记账（挂多模态对话）。
- **退出标准**：任意转账/收入/支出后，`Σdebit==Σcredit` 恒成立；导入支付宝账单零误差落库。

### Phase 1 — 最小闭环 + 首份 AI 报告（v1.0）⭐ 价值验证版
- **目标**：跑通「数据进 → 净资产 → AI 报告」闭环，验证核心假设。
- **交付**：净资产仪表盘（现金/储蓄/信用）；截图 OCR 记账；银行流水 CSV；首份**月度财务报告**（规则引擎 + LLM）；基础财务健康评分。
- **模型增量**：assets/liabilities（先支持现金·存款·信用，不含实物估值），snapshots（日快照 + 净资产曲线）。
- **AI**：规则引擎 v1（储蓄率/负债率/应急金）+ LLM 表达层；报告落文档/Block。
- **退出标准**：连续 30 天真实使用，净资产曲线与手动盘点一致；月报结论 0 幻觉（数字全来自规则）。

### Phase 2 — 资产/负债完整化（v2.0）
- **目标**：把「总资产 - 总负债 = 净资产」做全。
- **交付**：完整资产/负债明细（含房贷/车贷/信用卡/借款的 本金/剩余/利率/月供/到期）；实物资产（房产/车辆）带 `estimateConfidence` 单独标记；完整净资产曲线。
- **模型增量**：assets/liabilities 扩展，credit 账户账单周期/还款。
- **AI**：负债健康分析（月供收入比、去杠杆建议）。
- **退出标准**：一笔房贷/还款能正确减少负债、不影响资产、净资产曲线平滑反映。

### Phase 3 — 投资管理（v3.0）
- **目标**：持仓、市值、收益、收益率闭环。
- **交付**：投资账户 + `positions`（代码/数量/成本价/现价/市值/收益/收益率）；行情接入（股票/基金/黄金）；基金定投记录、累计投入、当前市值、**IRR**。
- **模型增量**：positions, investment_trades, instrument 行情缓存。
- **AI**：资产配置分析（股/债/金/现金占比）、集中度预警。
- **退出标准**：`银行卡 -100 → 基金 +100` 净资产不变、持仓 +100、成本正确；IRR 与主流计算器一致。

### Phase 4 — 家庭财务（v4.0）
- **目标**：多成员合并视图。
- **交付**：`families` / `family_members`；交易带 `memberId`（谁花/谁赚）；个人视图 + 家庭合并视图 + 共享权限。
- **模型增量**：families, members，交易归属字段。
- **AI**：家庭现金流、成员支出画像。
- **退出标准**：家庭视图净资产 = Σ成员净资产；权限边界正确。

### Phase 5 — 预算与目标（v5.0）
- **交付**：分类预算（已用/剩余/超支实时）；财务目标（买房/旅游/退休，完成率 + 预计达成时间）。
- **模型增量**：budgets, goals（派生字段）。
- **AI**：预算超支预警、目标进度建议。
- **退出标准**：超支实时触发；目标预计达成时间随结余率更新。

### Phase 6 — AI 财富顾问深化（v6.0）
- **交付**：现金流预测；智能预警（房贷占比过高/储蓄率下降/应急金不足）；个性化顾问对话；多期报告趋势对比；健康评分体系完整化。
- **AI**：预测（基于历史 + 规则）+ 个性化建议；高风险建议走审批闭环。
- **退出标准**：预警准确率达标（历史回测）；建议全部可追溯到规则结论。

### Phase 7 — 高级分析（v7.0）
- **交付**：资产负债深度分析、投资组合优化建议、个税规划（中国）、退休模拟、情景分析（what-if：失业/降薪/加息）。
- **AI**：情景模拟引擎 + 顾问解读。
- **退出标准**：what-if 结果与确定性模型一致。

## 9. 安全 / 合规 / 信任（横切，从 v0.5 起持续投入）

- **不存凭证**：永不存储银行/支付密码或登录态。所有数据来自用户主动导入/录入。
- **加密**：敏感金额字段应用层加密；传输 TLS；DB 静态加密。
- **local-first 选项**：核心账本可本地优先存储（仅同步到本设备），降低「把全部家底交出去」的信任门槛。
- **数据主权**：明确「数据归用户」，支持一键全量导出/删除。
- **合规免责**：AI 报告显著标注「非投资建议」；涉及税务/投资结论引用规则依据。

## 10. 北极星指标

- **主指标**：周活用户中「过去 7 天净资产曲线有更新」的占比（= 真正在管财富，而非伪记账）。
- 辅助：平均录入摩擦（每笔耗时）、数据完整度（账户覆盖率）、月报打开率、健康评分变化趋势。

## 附录 A — 从当前 schema 迁移

当前 `src/database/schemas/`：`auth / chat / mealRecords / palettes / rbac-extra / users`。
- `mealRecords` → 迁移为 `transactions(type=expense)` + `entries` + `category=餐饮`；保留旧表只读用于回溯，或写一次性迁移脚本。
- `chat`（多模态对话，009 分支）→ 复用为自然语言记账 + 账单 OCR 解析入口。
