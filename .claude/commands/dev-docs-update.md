# /dev-docs-update - 更新开发文档

在上下文重置或会话结束前更新现有的开发文档，确保所有进度都被保存。

**参数**: $ARGUMENTS（可选 - 任务名称）

---

## 🎯 你的任务

更新 `dev/active/` 中的开发文档，捕获当前会话的所有进度和发现。

---

## 📋 执行步骤

### 1️⃣ 识别要更新的任务

**如果用户提供了任务名称** ($ARGUMENTS 不为空):
```bash
TASK_NAME="$ARGUMENTS"
TASK_DIR="dev/active/$TASK_NAME"
```

**如果用户未提供任务名称**:
1. 列出 `dev/active/` 中的所有任务
2. 按最后修改时间排序
3. 选择最近修改的任务
4. 或询问用户选择哪个任务

```bash
# 查找最近修改的任务
ls -lt dev/active/
```

---

### 2️⃣ 读取当前状态

**读取三个文件**:
```
dev/active/[task-name]/
├── [task-name]-plan.md
├── [task-name]-context.md
└── [task-name]-tasks.md
```

**分析当前内容**:
- plan.md - 了解整体计划
- context.md - 查看上次的 SESSION PROGRESS
- tasks.md - 查看任务完成情况

---

### 3️⃣ 分析本次会话的变更

**检查项目变更**:
```bash
# 检查 git 状态
git status

# 查看最近修改的文件
git diff

# 查看最近的提交（如有）
git log --oneline -10
```

**识别完成的工作**:
- 创建了哪些新文件？
- 修改了哪些现有文件？
- 实现了哪些功能？
- 修复了哪些问题？

**识别进行中的工作**:
- 哪些任务开始了但未完成？
- 当前正在编辑哪个文件？
- 下一步需要做什么？

**识别新发现**:
- 发现了哪些新任务？
- 遇到了哪些技术约束？
- 做出了哪些重要决策？
- 有哪些阻塞项？

---

### 4️⃣ 更新 context.md

**更新 SESSION PROGRESS 部分**:

```markdown
## 🚦 SESSION PROGRESS

> 最后更新: [当前日期时间]

### ✅ 已完成
- [列出本次会话完成的所有工作]
- [具体文件名和功能]
- [测试结果]

### 🟡 进行中
- [当前正在做的任务]
- [具体文件: 路径]
- [进度百分比或状态]

### ⚠️ 阻塞项
- [列出遇到的问题]
- [需要的资源或决策]
```

**添加技术决策**（如有）:

```markdown
## 💡 技术决策

### 决策 X: [标题]
- **日期**: [YYYY-MM-DD]
- **决策**: [描述具体决策]
- **理由**: [为什么这样做]
- **替代方案**: [考虑过的其他方案]
- **影响**: [对项目的影响]
```

**更新关键文件**（如有新文件）:

```markdown
## 📁 关键文件

**新增: src/[path]/[file].ts**
- 用途: [描述]
- 状态: ✅ 已完成 / 🟡 进行中
- 关键功能: [列出]
```

**添加实施笔记**:

```markdown
## 📝 实施笔记

### [日期] - [主题]
[记录重要发现、问题、解决方案]

**问题**: [遇到的问题]
**解决方案**: [如何解决的]
**经验**: [学到的经验]
```

---

### 5️⃣ 更新 tasks.md

**标记已完成的任务**:
```markdown
- [x] **X.X** 任务描述
  - **文件**: `路径`
  - **验收**: ✅ 已验收
  - **完成时间**: [日期]
```

**更新进行中的任务**:
```markdown
- [ ] **X.X** 任务描述 (进行中 - 60%)
  - **文件**: `路径`
  - **当前状态**: [具体进度]
  - **下一步**: [下一步行动]
```

**添加新发现的任务**:
```markdown
- [ ] **X.X** [新任务描述]
  - **文件**: `路径`
  - **验收**: [验收标准]
  - **预估**: [时间]
  - **优先级**: 高/中/低
  - **依赖**: [依赖的任务]
```

**更新阶段状态**:
```markdown
## 🚀 阶段 X: [名称] ✅ 已完成

## 🔧 阶段 Y: [名称] 🟡 进行中 (60%)

## 🎨 阶段 Z: [名称] ⏳ 待开始
```

**更新总体进度**:
```markdown
## 📊 总体进度

- **总任务数**: X
- **已完成**: X (+N 本次会话)
- **进行中**: X
- **待开始**: X
- **完成度**: X% (+Y% 本次会话)
```

---

### 6️⃣ 更新 plan.md（如需要）

**仅在以下情况更新 plan.md**:
1. 范围发生重大变化
2. 发现新的阶段
3. 时间估算需要调整
4. 风险评估需要更新

**更新内容**:
- 添加新发现的阶段
- 调整时间估算
- 更新风险评估
- 修改成功指标

## 🎯 更新检查清单

在更新时，确保包含：

### context.md 必须更新:
- [x] SESSION PROGRESS 更新到当前状态
- [x] 已完成的工作列表完整
- [x] 进行中的任务准确
- [x] 阻塞项已记录
- [x] 新文件已添加到关键文件列表
- [x] 技术决策已记录（如有）
- [x] 实施笔记已添加（如有重要发现）
- [x] 快速恢复指南更新

### tasks.md 必须更新:
- [x] 已完成的任务标记为 [x]
- [x] 进行中的任务更新进度
- [x] 新发现的任务已添加
- [x] 总体进度百分比更新
- [x] 阶段状态更新（✅/🟡/⏳）

### plan.md 可选更新:
- [ ] 范围变更已反映
- [ ] 新阶段已添加
- [ ] 时间估算已调整
- [ ] 风险评估已更新

## 💡 更新最佳实践

### 1. 诚实准确
- ✅ 真实反映进度，不夸大
- ✅ 阻塞项立即记录
- ✅ 未完成的任务不要标记为完成

### 2. 具体详细
- ✅ "实现了 UserService.createUser() 方法"
- ❌ "写了一些代码"
- ✅ "遇到 MUI v7 Grid API 兼容性问题，已解决"
- ❌ "修了一些 bug"

### 3. 面向未来
- ✅ 下一步行动明确
- ✅ 阻塞项包含解决方向
- ✅ 进行中的任务说明剩余工作

### 4. 捕获决策
- ✅ 为什么选择这种方法
- ✅ 考虑过的替代方案
- ✅ 决策的影响

---

## 🔍 智能检测

**自动检测本次会话的变更**:

1. **Git 状态分析**
   ```bash
   git status --porcelain
   ```

2. **最近修改的文件**
   ```bash
   git diff --name-only
   ```

3. **推断完成的任务**
   - 对比 tasks.md 中的任务和实际创建/修改的文件
   - 自动建议标记为完成的任务

4. **发现新任务**
   - TODO 注释
   - FIXME 标记
   - 代码中的 // TODO 评论

---

## ⚠️ 重要提醒

1. **频繁更新** - 不要等到会话结束才更新
2. **保持诚实** - 进度反映真实状态
3. **记录决策** - 为什么这样做比做了什么更重要
4. **面向恢复** - 想象一个月后的自己能看懂
5. **包含上下文** - 不要假设你会记住所有细节
