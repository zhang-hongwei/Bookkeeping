为复杂任务创建持久化的三文件结构（plan + context + tasks），确保上下文重置后能快速恢复工作。

**参数**: $ARGUMENTS（任务描述）

## 🎯 你的任务

**任务名称**: $ARGUMENTS

---

## 📋 执行步骤

### 1️⃣ 分析任务范围

**分析以下内容**:
- 任务的复杂度（是否需要 dev docs）
- 涉及的技术栈组件
- 预估的实施时间
- 需要修改的关键文件

**技术栈参考**:
- Next.js 16 (App Router)
- React 19 + MUI v7 + Tailwind
- Zustand (状态管理)
- react-hook-form + Zod (表单)
- Drizzle ORM + PostgreSQL
- Clerk (认证)

---

### 2️⃣ 检查代码库

**搜索相关代码**:
```
- 类似功能的实现
- 相关的数据库 schema
- 相关的 API routes
- 相关的组件
- 相关的 services
```

**理解项目结构**:
```
src/
├── app/                   # Next.js App Router
│   ├── api/              # API Routes
│   └── (example)/        # 页面
├── components/           # React 组件
├── services/            # 业务逻辑
├── database/            # Drizzle schemas
└── store/               # Zustand stores
```

---

### 3️⃣ 创建目录结构

**目录名称规则**:
- 使用小写和连字符
- 简洁但描述性
- 例如: `implement-user-permission-system`

**创建目录**:
```bash
mkdir -p dev/active/[task-name]
```

## ⚙️ 技术约束

1. **MUI v7 兼容性**
   - 必须使用 `size={{ xs: 12 }}` 而非 `xs={12}`
   - Grid 不能有 `item` prop

2. **Next.js 16 App Router**
   - API routes 必须导出 GET/POST/PUT/DELETE 函数
   - 使用 NextRequest 和 NextResponse

3. **Clerk 认证**
   - API routes 需要认证检查
   - 使用 `auth()` 获取用户信息

4. **TypeScript**
   - 严格模式
   - 所有类型必须显式声明
