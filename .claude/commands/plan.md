# /plan 命令

为复杂任务创建结构化的开发计划：$ARGUMENTS

## 规划步骤

### 1. 分析需求
- 理解任务范围和目标
- 识别相关的代码文件和模块
- 评估当前实现状态

### 2. 创建计划结构

生成以下文件到 `dev/plans/[任务名称]/` 目录：

#### a) `plan.md` - 主计划文档
```markdown
# [任务名称] 开发计划

## 概述
- **目标**：明确要实现什么
- **范围**：包含和不包含的内容
- **优先级**：高/中/低
- **预计时间**：X 天/周

## 当前状态分析
- 现有实现：描述当前代码结构
- 存在问题：列出需要改进的点
- 技术债务：需要偿还的部分

## 实施阶段

### 阶段 1：准备工作
- [ ] 任务 1.1：xxx
- [ ] 任务 1.2：xxx

### 阶段 2：核心实现
- [ ] 任务 2.1：xxx
- [ ] 任务 2.2：xxx

### 阶段 3：测试和优化
- [ ] 任务 3.1：xxx
- [ ] 任务 3.2：xxx

## 风险评估
- **技术风险**：可能遇到的技术挑战
- **依赖风险**：外部依赖或团队依赖
- **时间风险**：可能的延期因素

## 成功标准
- [ ] 功能完整性：所有需求已实现
- [ ] 测试覆盖：>80% 代码覆盖率
- [ ] 性能达标：满足性能要求
- [ ] 文档完善：代码和使用文档齐全
```

#### b) `context.md` - 上下文信息
```markdown
# [任务名称] 上下文

## 关键文件
- `src/xxx/xxx.ts` - 作用说明
- `src/yyy/yyy.tsx` - 作用说明

## 技术决策
1. **决策**：选择 X 而不是 Y
   - **原因**：xxx
   - **影响**：xxx

## 依赖关系
- 依赖模块：xxx
- 被依赖模块：xxx

## 参考资料
- 相关 PR：#123
- 设计文档：link
- API 文档：link

最后更新：YYYY-MM-DD
```

#### c) `tasks.md` - 任务清单
```markdown
# [任务名称] 任务清单

## 🚀 进行中
- [ ] 任务名称
  - 描述：xxx
  - 验收标准：xxx
  - 工作量：S/M/L/XL

## ✅ 已完成
- [x] 已完成的任务

## 📋 待办
- [ ] 待办任务

最后更新：YYYY-MM-DD
```

### 3. 任务分解原则

每个任务应该：
- **明确可验证**：有清晰的完成标准
- **合理大小**：1-4 小时可完成
- **独立性**：尽量减少依赖
- **优先级排序**：按价值和风险排序

### 4. 工作量评估

- **S (Small)**：1-2 小时
- **M (Medium)**：2-4 小时
- **L (Large)**：4-8 小时
- **XL (Extra Large)**：8+ 小时（需要进一步拆分）

## 使用场景

### ✅ 适合使用 /plan 的场景
- 重构现有功能
- 实现复杂的新特性
- 架构变更
- 性能优化项目
- 多步骤迁移

### ❌ 不适合的场景
- 简单 bug 修复
- 单文件修改
- 紧急热修复

## 计划模板

根据任务类型选择合适的模板：

### 功能开发模板
1. 需求分析
2. API 设计
3. 数据模型设计
4. 前端实现
5. 后端实现
6. 测试
7. 文档

### 重构模板
1. 识别问题代码
2. 设计新架构
3. 编写测试保护
4. 逐步重构
5. 验证功能
6. 清理旧代码

### 性能优化模板
1. 性能基准测试
2. 瓶颈识别
3. 优化方案设计
4. 实施优化
5. 对比测试
6. 监控部署

## 最佳实践

1. **先规划后编码**：复杂任务一定要先制定计划
2. **持续更新**：每次会话结束更新进度
3. **记录决策**：重要的技术决策要记录原因
4. **定期回顾**：检查计划是否需要调整
5. **知识沉淀**：完成后总结经验教训

## 与其他命令配合

```bash
# 1. 创建计划
/plan 重构用户认证系统

# 2. 开始开发
/dev

# 3. 定期分析进度
/analyze

# 4. 构建测试
/build

# 5. 保存上下文（会话结束前）
/save-context
```

## 输出示例

执行 `/plan 实现用户权限管理` 后，会生成：

```
dev/plans/user-permission-management/
├── plan.md           # 详细的开发计划
├── context.md        # 技术决策和上下文
└── tasks.md          # 可追踪的任务清单
```
